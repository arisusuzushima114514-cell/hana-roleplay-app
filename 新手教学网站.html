先让应用能回复，再做角色和剧情。无需一次理解所有功能。

阶段 01

下载并打开 Hana

从项目发布页获取 APK。Android 通常会提示“未知来源应用”，这是直接安装 APK 时的系统提示。

  • 下载后点 APK 安装。
  • 首次打开先允许必要权限。
  • 进入设置页，不必先创建角色。
完成标志：能看到 Hana 的主界面。
阶段 02

选择并获取 API

Hana 负责角色、上下文和界面；模型回复由你自己的 API 服务商提供。任选一个服务商即可开始。

DeepSeek 官方平台推荐新手先使用。注册后进入 API Keys 创建密钥。api.gemai.cc第三方兼容 API 示例。先查看其后台、密钥说明、模型列表与兼容文档。
第三方服务的费用、隐私、模型来源、服务条款及稳定性需要你自己确认；不要把 API Key 给陌生人。
阶段 03

创建 API Key

以 DeepSeek 为例：在平台登录后打开 API Keys 页面，创建一个新 Key 并立即复制保存。

打开 DeepSeek API Keys
  • Key 只在创建后完整显示一次。
  • 不要发到聊天群、截图或角色卡里。
  • 怀疑泄露就到平台删除并新建。
完成标志：你手上有一串 API Key。
阶段 04

在 Hana 填写服务商

打开 设置 → 模型与服务商 → 添加服务商，填写名称、API Key、基础 URL 和模型名。

DeepSeek URL: https://api.deepseek.com/v1模型示例: deepseek-chat

基础 URL 少了末尾 /v1 时，Hana 会自动补上一次。第三方服务请以它自己的兼容文档为准。

完成标志：保存后能在模型列表看到它。
阶段 05

先发送一次测试

新建一个普通会话或角色会话，发送一句简单的话，例如“你好，请用一句话介绍自己”。

  • 有回复：API 配置完成。
  • 401 / 未授权：多半是 Key 错误或失效。
  • 404：重点检查基础 URL 和模型名。
  • 超时：检查网络、余额和服务商状态。
完成标志：应用收到模型回复。
阶段 06

创建第一张角色卡

创建角色时先只填四项，先让角色能稳定说话，再逐步补细节。

  • 名称：角色如何被称呼。
  • 性格：写可观察的行为和说话方式。
  • 设定：身份、关系、世界背景。
  • 开场白：你打开会话时看到的第一段。
比起“温柔、神秘”，写“回答前会停顿，习惯把不安藏进玩笑里”更容易生效。
阶段 07

导入角色卡，或写剧情前言

已有角色卡可在角色页导入 JSON 或 PNG。导入后先检查名称、头像、开场白、设定是否齐全。剧情前言适合写“当前正在发生什么”，它会在本轮对话优先参考。

剧情前言示例：雨夜的列车即将到站。你和林澈因争吵坐在相邻车厢，谁都还没有先开口。
  • 在角色编辑页填写的剧情前言，会带入之后新建的角色会话。
  • 已有会话不会被自动覆盖，避免旧剧情被改掉。
  • 聊天页顶部也可修改当前会话的剧情前言。
阶段 08

用具体动作推进聊天

模型更容易理解“发生了什么、你做了什么、希望它怎么回应”。不要只说“继续”。

我把伞向你那边倾斜一点，没有追问，只说：先回家吧。场景切到三天后。请保持两人刚和好的克制感，不要直接告白。

角色跑偏时，直接补充具体规则，例如：“保持冷淡但不失礼，不要替我决定行动。”

阶段 09

理解关系与多角色

正常公开对话会让关系缓慢变化。明确承诺、亲密、冲突或威胁等强事件，变化会更快。

  • 单角色：专注一对一剧情。
  • 多角色：仅在角色模式选“多角色”时启用。
  • 群像场景：轮流点名发言，避免模型漏人。
创作预设影响本地剧情、文风和上下文组织，不保证绕过任何模型或服务商的服务端限制。
阶段 10

选择模型并保存数据

长剧情、复杂角色卡、多角色场景更适合 DeepSeek API、Pro 或深度思考类模型；Flash 类通常适合低成本短对话。

  • 导出前确认文件存放位置。
  • 当前导出不是应用内“一键完整恢复备份”。
  • 更换手机前，保留角色卡和重要聊天的独立副本。
现在你已经可以从角色卡开始写第一段剧情。
